# 微信平台的硬边界

这是兼容性约束，不是风格指南。这里没写的一切都由你自己决定。

## 正文片段

- 提交的是 HTML **片段**，不是完整文档。不要 `<html>`、`<head>`、`<body>`。
- 样式全部写在元素的 `style` 属性上。`<style>` 块、外链样式表、外链字体、脚本、事件处理、表单、iframe 会被丢掉或改坏。
- 微信会删除或重新解释部分标签与 CSS 属性。含义、阅读顺序和必要信息必须在被清理之后依然成立——动画和交互不能承载关键信息。
- 带样式的容器一律用 `<section>`，不要用 `<div>`。见下方“网页编辑器”。

## 网页编辑器（mp.weixin.qq.com）

草稿进了草稿箱，运营同事很可能会在后台网页编辑器里打开、改字、点“保存为草稿”。正文必须扛得住这一步。

- 编辑器（ProseMirror）会把每个 `<div>` 转成 `<p>`，并**丢掉它的全部内联样式**，打开时就转，保存后写回草稿。用 `div` 搭的版式，被人在网页里保存一次就整篇塌掉，API 读回也只剩 `p` / `img` / `span`。
- `<section>`、`<p>`、`<span>`、`<b>` 上的内联样式都能原样保留：flex、gap、inline-block、负 margin、box-shadow、border-radius、`font:` 简写都实测存活。
- 编辑器保存时还会：给每条 `style` 末尾补 `;`，把文字包进 `<span leaf="">`，删掉 `<img>` 的 `alt` 属性。正文会因此变长。
- 把已有的 `div` 版正文整体替换成 `section`（开闭标签一起换，其他不动），版式不变：实测 320px / 375px 下 249 个元素的位置尺寸逐一相同。
- 验证方法：用一篇“测试勿发”的草稿，在网页编辑器打开并保存，再 API 读回比对。不要拿正式草稿做试验。

## 文章页的继承样式

正文在文章页里放在 `#js_content` 容器内，它会给所有子元素继承 `font-size:17px; letter-spacing:0.544px; text-align:justify; line-height:1.6`；375px 宽的手机上正文栏约 335px。

- 草稿 API 读回的内联样式一字不差，所以只比对 HTML 发现不了这类问题。
- 根容器上显式写 `letter-spacing:normal; text-align:left`（或你要的值）、字号、行高，别依赖继承。固定宽度的短行（如书名行）尤其容易被字距撑到折行。
- 本地预览要模拟上面这组继承值和 335px 栏宽才可信。
- `Noto Serif SC`、`Microsoft YaHei` 这类字体在 Windows 开发机上有、手机上多半没有，本地“字体一致”的检查没有意义。字体栈要写手机上真有的。

## 长度

- 投递服务对 `content` 有 19999 字符上限，超出直接返回 HTTP 422，什么都不写入。改稿时要留余量。
- 在网页编辑器保存过的正文会变长（见上），再从 API 改它时可能超限。
- `draft-update` 成功后，读回立刻是新内容，但临时预览链接可能几分钟内仍显示旧版。以读回为准，过一会儿再看预览。

## 图片

- 正文图的 `src` 必须是 `image-upload --mode article` 返回的微信托管地址。微信可能返回 `http://mmecoa.qpic.cn` 或 `http://mmbiz.qpic.cn`，客户端会统一改写成 HTTPS 的 `https://mmbiz.qpic.cn`，路径和查询参数保留。
- 本地路径、data URL、临时对象地址、无法访问的外部图床都不可靠。
- 宽高建议写死成与栏目同宽的数值（或 `max-width:100%;height:auto`），避免超出正文栏。
- 封面必须按永久素材上传（`--mode material`），返回的 `media_id` 填进 `thumb_media_id`。

## 排版容错

- 不要用空定位元素 + CSS 图形去做首屏关键视觉。实测这类纯 CSS 装饰在草稿预览里会被清掉，背景和文字留下、图形消失；关键画面请渲染成图片走上传流程，其余 HTML/CSS 各司其职。
- SVG 与 SMIL 能不能活下来取决于具体元素和属性。文字和阅读顺序不要放进动画层；给出有意义的静态首帧。没在真实草稿里验证过的写法，不要当成已验证。
- 记录：草稿 API 会保留 `svg` / `rect` / `circle` / `path` / `ellipse`，以及 SMIL `animate` 对 `opacity` 的动画；会去掉对 `rx` / `cy` 等几何属性的 `animate`，也会去掉 `referrerpolicy`。这只是草稿 API 的行为，手机端仍需实测。

## 自适应

- 不横向滚动，不裁切，不重叠。
- 媒体和图形不能比正文栏更宽。
- 文字与背景在被处理后仍要清晰可辨，装饰层不能盖住内容。
- 浏览器里好看不算数，被清理后的手机草稿才是最终结果。保留一份与提交内容完全一致的本地 HTML 作对照，差异可以直接比对，不用猜。
